# Module Spec: UI 多语言支持（i18n，简体中文 + English）

## 1. Overview

为扩展的三个界面表面（**popup / 侧边栏 Side Panel / options 页**）增加多语言能力，
支持 **简体中文** 与 **English**，语言选择方式为「**跟随系统语言 + 设置内手动覆盖**」（用户已确认）。

当前 UI 全部为中文硬编码（约 224 处，分布在 21 个文件），本模块将其替换为 key 驱动的 `t()` 翻译调用。

## 2. Interface / API Contract

### 2.1 语言模型

- 语言标识：`'zh-CN' | 'en'`（全小写 `'zh'` / `'en'` 作为 fallback 兼容）。
- 存储 key：`chrome.storage.local['ui_lang']`，取值：
  - `'auto'`（默认）→ 跟随 `navigator.language`（`zh*` → zh-CN，其余 → en）
  - `'zh-CN'` / `'en'` → 手动覆盖
- 三个表面（popup / side panel / options）各自独立读取同一 storage key，加载到内存后响应语言变化。

### 2.2 核心模块（纯 TS，可单测）

```ts
// frontend/src/i18n/index.ts
export type Lang = "zh-CN" | "en";
export type Dict = Record<string, string>;

export function detectLang(navigatorLang: string, override?: string): Lang;
// override: 'auto'|'zh-CN'|'en'；override 为 'auto' 或缺失时按 navigatorLang 推断

export function makeTranslator(lang: Lang): (key: string, params?: Record<string, string | number>) => string;
// t(key) 查找顺序：当前语言 dict → 另一语言 dict → 返回 key 本身（调试可见）
// 支持 {param} 占位符插值，如 t("profile.active", { name })

// 字典完整性校验（供测试/CI）：
export function assertDictComplete(zh: Dict, en: Dict): string[];
// 返回只在单侧出现的 key 列表（空数组 = 完整）
```

### 2.3 React 集成（轻量自研，不引入 react-i18next）

```ts
// frontend/src/i18n/I18nProvider.tsx
// <I18nProvider> 包裹三个入口（main.tsx / popup.tsx / options.tsx）
// useI18n(): { lang: Lang, t: (key, params?) => string, setLang: (l: "auto"|Lang) => void }
// setLang 写入 chrome.storage.local['ui_lang'] 并触发 re-render
```

### 2.4 词典结构

```ts
// frontend/src/i18n/locales/zh.ts / en.ts
// 扁平 key，按表面+组件分组命名，例如：
//   common.save / common.cancel
//   proxy.title / proxy.profileActive
//   popup.quickHeaders
//   options.tabs.general / options.tabs.proxy ...
```

### 2.5 background / 动态消息处理策略

- **UI 组件内部生成的 flash/toast 文案**（如 `flash("已保存并应用")`）：在组件内用 `t()` 生成，**保持现有 `flash(text)` 签名不变**。
- **background `appendLog` 运行时日志**：属于调试诊断信息，**不在本模块翻译范围**（保持原文，避免 worker 内状态管理复杂化）。UI 渲染时不做翻译。

## 3. Acceptance Criteria (BDD)

### Feature: 语言检测与覆盖

#### Scenario 1: [SPEC-I18N-001] 跟随系统语言
- **Given** `ui_lang` 未设置或为 `'auto'`
- **When** 浏览器语言为 `zh-CN` / `zh-TW` / `zh` 等 `zh*` 前缀
- **Then** `detectLang` 返回 `'zh-CN'`；非 zh 前缀（如 `en-US`、`de`）返回 `'en'`
- **Mapped Test:** `testings/i18n/detect.test.ts`

#### Scenario 2: [SPEC-I18N-002] 手动覆盖优先
- **Given** 系统语言为中文，`ui_lang` 已手动设为 `'en'`
- **When** 用户打开任一表面
- **Then** UI 显示英文；更改 `ui_lang` 后重新打开仍为英文
- **Mapped Test:** `testings/i18n/persist.test.ts`

### Feature: 翻译解析

#### Scenario 3: [SPEC-I18N-003] key 查找与占位符
- **Given** zh/en 词典均含 `proxy.active`（zh: `代理 {name} 已激活`，en: `Proxy {name} activated`）
- **When** 调用 `t("proxy.active", { name: "SOCKS5" })`
- **Then** 中文环境返回 `代理 SOCKS5 已激活`，英文环境返回 `Proxy SOCKS5 activated`
- **Mapped Test:** `testings/i18n/translate.test.ts`

#### Scenario 4: [SPEC-I18N-004] 缺失 key 的降级
- **Given** 当前语言 en，某 key 仅存在于 zh
- **When** 调用 `t("only.zh.key")`
- **Then** 返回 zh 原文（fallback）；两侧都缺失时返回 key 本身，不抛异常
- **Mapped Test:** `testings/i18n/translate.test.ts`

### Feature: 词典完整性（CI 回归保护）

#### Scenario 5: [SPEC-I18N-005] 中英 key 集合一致
- **Given** `locales/zh.ts` 与 `locales/en.ts`
- **When** 运行 `assertDictComplete(zh, en)`
- **Then** 返回空数组（无单侧缺失 key）；若有缺失返回缺失列表且测试失败
- **Mapped Test:** `testings/i18n/dict-complete.test.ts`

### Feature: 三表面覆盖

#### Scenario 6: [SPEC-I18N-006] popup / side panel / options 全部可译
- **Given** `I18nProvider` 已包裹 main.tsx、popup.tsx、options.tsx
- **When** 用户切换语言
- **Then** 三个表面全部以所选语言渲染（抽查各表面代表性文案通过 t() 渲染）
- **Mapped Test:** `testings/i18n/surfaces.test.ts`

## 4. 不在本 Spec 范围内

- background `appendLog` 运行时日志的翻译（保持原文）
- Chrome Web Store 商店描述/权限说明的多语言（后台单独设置）
- 繁体中文及其他语言（后续可扩展，词典结构已支持）
- 动态 HTML（`dangerouslySetInnerHTML`）内容的多语言

## 5. 技术选型说明

采用**轻量自研**方案（React Context + 扁平词典 + `t()` 函数），**不引入 react-i18next 依赖**：
- 现有依赖仅 react/react-dom，保持最小化；Vite bundle 体积更小
- 词典为纯 TS 模块，可直接被 `node --experimental-strip-types` 单测，无需 mock chrome
- 语言切换通过 provider state 驱动，无需页面重载
